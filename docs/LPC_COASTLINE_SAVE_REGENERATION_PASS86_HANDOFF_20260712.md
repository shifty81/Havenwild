# Havenwild LPC Coastline + Save Regeneration Pass 86

Date: 2026-07-12

## Result

Pass 86 corrects the two separate problems visible in the supplied client screenshot:

1. The active gameplay slot kept its previously serialized island silhouette because
   `WORKSPACE/saves/slot_<n>/world.tworld` is authoritative. Rebuilding project
   content or regenerating the native-editor project world does not silently replace
   an occupied gameplay slot.
2. Several LPC cells were being used for the wrong purpose. Deep water repeated
   pieces from the large circular pond stamp at rows 20-25, while the Pass 85
   transition baker converted broad material regions into white masks. This produced
   the vertical/circular deep-water fragments and the white triangular coastline
   wedges seen in the runtime.

## Existing gameplay save workflow

The client save metadata generation version is now **3**.

Occupied save cards now expose:

- **Play**
- **Update World** when the slot was generated by an older version
- **Regenerate** when it already uses the current version
- **Open Folder**
- **Delete**

Update World and Regenerate rebuild the slot from its existing seed and launch the
rebuilt world. A confirmation explains that this replaces the slot world, previews,
runtime edits, paint deltas, and current gameplay progress. The operation is explicit
rather than automatic so a new build cannot silently destroy an authored save.

For the existing Slot 1 shown in the screenshot:

1. Build and launch `HavenwildClient.exe`.
2. Return to the save-slot screen.
3. Slot 1 should show `generation v2 | update available`.
4. Select **Update World**.
5. Confirm **Regenerate**.

The world is rebuilt from the same seed with the organic Pass 85/86 coastline raster.
Simply selecting Play continues loading the old serialized `world.tworld` by design.

## LPC base-terrain correction

`content/assets/intake/lpc_terrain_promotion_v0_2.json` now distinguishes repeatable
terrain from multi-tile stamps.

Corrected water behavior:

- Open-water source cells: `[12,16]`, `[13,16]`, `[14,16]`, `[15,16]`
- Shallow-water source cells: `[12,17]`, `[13,17]`, `[14,17]`, `[15,17]`
- Deep and ocean-deep variants are deterministic color grades of the repeatable
  open-water cells.
- Circular pond components from rows 20-25 are no longer used as repeatable water.
  They remain candidates for later multi-tile pond stamps.

This removes the repeated vertical arcs, circular gradients, grass fragments, and
rock fragments from deep ocean tiles.

## Transition-atlas correction

The Pass 85 transition baker compared composed material tiles against a transparent
center cell. Nearly every opaque source pixel therefore became a white replacement
mask. The runtime tinted some of those masks, while the native editor rendered them
white directly.

Pass 86 replaces that path with:

- Direction-correct extraction from standard LPC 3x3 edge/corner blocks.
- The standard riverbank block for shoreline contour geometry.
- No use of the circular pond block as a 4-way shoreline set.
- Material-region classification followed by a narrow alpha contour.
- No fully opaque pixels in the generated transition atlas.
- Shared semantic tint behavior in both the runtime and native editor.
- Reduced transition opacity so source terrain remains visible beneath the contour.

The existing manifest path and group IDs remain stable:

`assets/generated/worldgen_v0_1/terrain/terrain_autotile_47_32.json`

The manifest is now version `0.3.0` and remains compatible with the existing
N=1, E=2, S=4, W=8 request path.
