## Mapper: executable first slice of iterative mapping workflow

1. Open existing `apps/haven_atlas_mapper_lite`, activate Summer/neutral ElizaWy sheets in the left source stack, and open/save a **corrected reference scene** in the right canvas. Old source pixels remain read-only.
2. Use `Reassemble saved scene + missing` in the right inspector (`Ctrl+M`). A new pass leaves **all existing pieces and their positions, source identities, elevation 0..30, water and authored details untouched**. It finds source cells with actual nontransparent pixels which are not represented by any piece in the active saved scene. Up to 24 are placed in an explicitly labelled correction tray to the right, never secretly applied to cliff or water geometry. Save first: dirty/unsaved scenes refuse Reassemble.
3. Move correction-tray pieces into appropriate locations and set specific semantic roles, then save, run Audit and Review PNG. `Learn from corrected scene` refuses unsaved scenes and any remaining `unresolved.source_cell` pieces. Learning is a *candidate* record, not visual or gameplay approval.
4. Candidate handoff JSON now embeds `iteration_coverage` for every activated source: nonempty source cell count, represented count, learned-candidate count, approved count, unresolved cells and exact missing coordinates. `generation_passes` identifies the loop iteration. The project and review PNG remain separate saved evidence, not sources generated by AI.
5. Run `py -3 apps\haven_atlas_mapper_lite\tools\package_iteration.py --project "YOUR.mapper.json" --png "YOUR_SOURCE_REVIEW.png" --handoff "YOUR_handoff.json" --audit "YOUR.scene-audit.json" --out "YOUR_iteration.zip"` to obtain one uploadable ZIP. The packager checks the saved project, review ledger, handoff placements/heights and source IDs match; hashes every included file; rejects mismatched revisions; sets UNREVIEWED candidate status. No original source sheets embedded. Run independent `verify_review.py` to replay pixels before asking for visual approval.
6. Share one ZIP per correction iteration for external assessment; approved exact recipes **will eventually** feed the shared Asset Authority/worldgen/editor/client. This patch does not implement that publication stage.

### Meaning of atlas badges (corrected)

- Amber `?`: source cell merely placed / draft, including algorithmically guessed roles.
- Blue `L`: mapping was learned from a corrected saved scene; still awaiting source-exact grammar and approval.
- Green `✓`: requires explicit per-cell `approved_mapping` status; a whole-sheet green state also requires 100% nontransparent-cell coverage and validated/visually approved lifecycle. The mapper does **not** manufacture approvals in this pass.
- Empty/padding cells are excluded from denominator (e.g., source sheet with 42 addresses and 40 actual nontransparent cells). Actual suitability of partially transparent role cells remains subject to visual review.
