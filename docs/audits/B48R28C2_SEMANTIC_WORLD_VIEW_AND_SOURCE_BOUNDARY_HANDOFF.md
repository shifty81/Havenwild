# B48R28C2 — Semantic world view, guarded source staging, and shared mapping boundary

## Baseline and intent

- GitHub `shifty81/Havenwild` branch `experimental` verified at `78ff838499015ff434dbd935ae5daf9cbd11a02e` (`B48R28B - certified GREEN`). This package **supersedes the uncommitted B48R28C1 transport** and contains all its payload files as a cumulative B48R26–B48R28C2 patch. It is **not** a complete source rollup.
- This is an isolated Bevy + pinned ForgeGUI candidate. Legacy renderer, simulation, mapper, client, save paths, canonical assets and original ElizaWy files are preserved. No project-owned PCC replacement, alternate source database, alternate world, or new root launcher is created.
- The purpose of R28C2 is to make *actual* source/scene topology visible and inspectable **without pretending that scene semantics are visually mapped**. The required certified source-exact ElizaWy resolver is NOT delivered in this pass.

## Concrete changes

1. Existing PCC has a fifth registered command, `experimental.bevy.scene-plan` (Build & Verify and World/terrain menus), routed through existing `PccCommandHost.ps1` → existing `HavenwildBevyCandidate.ps1` → `candidate_gate.py`. The Status/Verify/Build/Run commands remain. No duplicate job/patch authority.
2. `tools/semantic_scene_plan.py`: deterministic, renderer-neutral semantic input from the **real fixture bytes**. It validates SHA, scene identity, strict 32px rectangular grid, at most 65,536 cells, exact north/east/south/west neighbor roles; outputs stable x/y ordering, counts, and **NULL visual source rectangles**. Writes only ignored candidate-local evidence via atomic replacement. No colors, source rects, fabricated mapping, transforms, elevation, collision or game-state changes are generated by the compiler.
3. Build and Run automatically regenerate that evidence after the existing experimental-lane, source, license/credits and scene verification. `scene-plan` allows explicit inspection without Cargo. The Rust candidate requires and independently rechecks the receipt, source/scene hashes, credits SHA, every cell and its neighbors, role totals and unapproved status.
4. ForgeGUI's existing candidate shell now presents the real 40×28 river fixture in a separate **Semantic Debug** center tab. Each cell displays an explicitly labeled diagnostic swatch derived from its real semantic role; select a cell to inspect stable scene identity/fixture SHA, coordinates and exact role. The original ElizaWy atlas stays in a separate real Bevy GPU source-preview tab. Source and world selections are distinct; clicking one never assigns the other. There are no authoring writes.
5. Source preparation now checks that Git is available, branch is `experimental`, and B48R28B GREEN is an ancestor **before any staging writes**. It refuses staging directory symlink redirection. The existing candidate gate now validates the staging receipt's experimental lineage and parent symlinks.
6. Added a machine-readable ElizaWy draw-plan publication boundary contract for the *next* mapping/compiler pass. It requires original SHA/credits, mapper-authored roles and exact rectangles, reviewed board-specific approval, validated collision/nav/animation references, strict family isolation and atomic publication. The existing V7-only draw-plan is deliberately not impersonated as ElizaWy.

## Actual source evidence, not artist approval

The source file `content/worldgen/scenes/terrain_acceptance/river_scene_v1.json` was byte-compared to the same Git blob SHA in GitHub B48R28B: `4294eb4895745cdceaa48c5bece1470d3d2bf5c5`. Pure-plan analysis of those bytes produced 1,120 cells: Grass 868; RiverWater 196; MudBank 56. The plan states **1,120 UNMAPPED and zero approved draw calls**. This is the correct result until source-exact mapper recipes are reviewed, approved and published. This old fixture is a diagnostic scene; it is not the complete summer multi-level demonstration scene requested for art review.

The colored semantic UI is **not a rendered ElizaWy world**, and its appearance is not approval of terrain, waterfalls, collision, +1 elevations or seasonal variants. The original atlas preview is source-exact but not an assembled scene. No visual evidence was synthesized or silently substituted. The `content/assets/intake/lpc_terrain_family_mapping_v0_3.json` historical base tile coordinates are not auto-promoted or assigned to scene roles.

## Run after applying via the existing experimental PCC

Use the latest cumulative ZIP only; do not stack it with R28C1. Keep original `Terrain.zip` available for the existing candidate's `prepare_source.py` step if not already staged. Through the **same Havenwild PCC**, run Status → Verify → `Bevy candidate: semantic scene plan` → Build → Run, inspecting the semantic grid and source preview in separate center tabs. The candidate's five stable keys are available from ForgePY's existing project PCC provider. Full Quality Gate and Windows graphical checks are still mandatory.

PCC Build/Run is intentionally blocked if original source, credits, source stage receipt, current river fixture, lineage or semantic evidence is inconsistent. The compiler does not read or write canonical saves. Direct Cargo run requires a plan receipt; the PCC run command creates it automatically.
