# Havenwild Package Metadata BOM Audit — Pass167Z62

## Finding

Windows PowerShell 5.1 `Set-Content -Encoding UTF8` emits a UTF-8 BOM. Havenwild's package tool used that path for both `.havenwild/package-baseline.json` and staged `manifests/packages/Pass<id>-package.json` files.

The normal content validator correctly rejected BOM-prefixed owned JSON, but `.havenwild` should never have been scanned as owned source. This created two distinct defects:

1. Machine-local package state could block every build.
2. Package manifests generated by the same writer entered source rollups with a BOM.

## Resolution

`PackageProject.ps1` now owns one `Write-Utf8NoBom` helper using `System.Text.UTF8Encoding(false)` and `System.IO.File.WriteAllText`. Baseline JSON, package-manifest JSON, and patch-removal manifests route through this helper.

`validate_project_content.py` now excludes `.havenwild` alongside other machine-local, generated, imported, and build-output roots. It continues reading owned JSON with strict `encoding="utf-8"`; source files are not silently normalized with `utf-8-sig`.

The existing `manifests/packages/Pass167Z59-package.json` was rewritten without its BOM.

## Regression coverage

The validator self-test creates a malformed BOM-prefixed `.havenwild/package-baseline.json` and confirms it is skipped, then creates malformed owned JSON under `content/` and confirms that it still fails validation.
